- Operating-system information
- Counts for all vulnerability severities

- A deterministic deployment decision calculated by the security quality gate

Generate the report using the exact structure below.

# AI Container Security Assessment

## 1. Executive Summary

Summarize the overall security posture of the container image.

Mention:

- Total number of vulnerabilities
- Number of Critical vulnerabilities
- Number of High vulnerabilities
- Overall deployment risk

Keep this section concise.

## 2. Container Information

Present:

- Image name
- Artifact type
- Operating-system family
- Operating-system version or name

## 3. Vulnerability Summary

Create a Markdown table with these columns:

| Severity | Count |
|---|---:|

Include:

- Critical
- High
- Medium
- Low
- Unknown
- Total

## 4. Critical and High Findings

Create a Markdown table with these columns:

| Vulnerability ID | Package | Installed Version | Fixed Version | Severity | Target | Risk |
|---|---|---|---|---|---|---|

Include only Critical and High findings.

For the Risk column, briefly explain the possible security impact based on the
vulnerability title and supplied metadata.

Do not include Medium or Low findings in this table.

When no fixed version is available, state:

No fixed version currently available

## 5. Remediation Priorities

Organize remediation into:

### Immediate Actions

Describe actions required for Critical vulnerabilities.

### High-Priority Actions

Describe actions required for High vulnerabilities.

### Image Maintenance Actions

Recommend:

- Rebuild the image using the latest patched version of the same supported
  Python base-image family
- Pin the base image by version or digest where practical
- Upgrade vulnerable operating-system packages through a clean image rebuild
- Upgrade vulnerable Python dependencies to fixed versions
- Remove unnecessary packages
- Re-run Trivy after remediation

Do not recommend downgrading Python.

Do not recommend changing the application image to ubuntu:latest.

## 6. Dockerfile Hardening Recommendations

Provide practical recommendations such as:

- Use a supported and patched Python slim base image
- Pin the image version or digest
- Run the application as a non-root user
- Use COPY instead of ADD unless ADD is specifically required
- Avoid installing unnecessary operating-system packages
- Use --no-install-recommends for apt packages
- Remove apt cache files in the same RUN instruction
- Install Python packages using a pinned requirements file
- Use pip with --no-cache-dir
- Avoid embedding secrets in the image
- Consider a multi-stage build when build tools are required
- Add a health check when appropriate

Do not provide an incorrect Dockerfile that changes the application to an
unrelated base image.

## 7. Runtime Hardening Recommendations

Recommend appropriate runtime controls such as:

- Run as a non-root user
- Use a read-only root filesystem where possible
- Drop unnecessary Linux capabilities
- Disable privilege escalation
- Set CPU and memory limits
- Use seccomp or AppArmor
- Avoid privileged containers
- Mount secrets at runtime rather than embedding them in the image
- Use network restrictions where appropriate

## 8. Deployment Recommendation

Use the deployment decision supplied in the scan data.

Return exactly one of:

ALLOW

or

BLOCK

Do not provide alternative decisions.

Explain that the decision applies to promotion or deployment of the container
image.

Do not describe the decision as blocking incoming network traffic.

## 9. Overall Risk Rating

Return exactly one rating:

Low

Medium

High

Critical

Use the following guidance:

- Critical vulnerabilities present: Critical
- No Critical vulnerabilities but High vulnerabilities present: High
- Only Medium vulnerabilities present: Medium
- Only Low or no vulnerabilities present: Low

## 10. Validation Steps

Provide commands or actions to:

- Rebuild the container image
- Re-run the Trivy scan
- Compare vulnerability counts
- Re-run the Container Hardener Agent
- Confirm whether the security gate changes from BLOCK to ALLOW

Keep the full report concise and technically accurate.
